# Plan: Endpoint `GET /api/v1/availability-per-day`

## Input (ยืนยันแล้ว)
- `start_date` — required, date, after_or_equal:today
- `end_date` — required, date, after_or_equal:start_date
- cap: (end − start) ≤ 365 คืน → เกินปฏิเสธด้วย 422 (DoS guard สำหรับ route public)

## Output — คืน **ทุก room type** ในระบบ (ไม่ filter)
```json
{
  "status": "success",
  "message": "Per-day availability fetched successfully",
  "start_date": "2026-08-10",
  "end_date": "2026-08-12",
  "room_types": [
    {
      "room_type_id": "uuid",
      "name_en": "Deluxe",
      "name_th": "ดีลักซ์",
      "2026-08-10": 8,
      "2026-08-11": 7,
      "2026-08-12": 9
    },
    { ... ทุก room type ... }
  ]
}
```
แต่ละค่า = จำนวนห้องว่าง "คืนนั้น" = `max(0, total − occupied)` เฉพาะคืนนั้น (half-open: check_in ≤ D < check_out)

## Semantics (ล็อกจากการ scrutinize)
- **Total rooms (ตัวตั้ง)** = ห้องที่ `status NOT IN (maintenance, reserved_closed)` → ตรงกับ `BookingController::createBooking` (snapshot ณ today, ไม่ over-promise)
- **Occupied** = booking_rooms ที่ status ∈ (draft, confirmed, checked_in) และ overlap คืนนั้น (ตรงกับ `/availability` เดิม 100%)

## ไฟล์ที่แก้ (3 ไฟล์)

### 1. `app/Http/Controllers/Api/V1/RoomController.php`
เพิ่ม method `availabilityPerDay()` ถัดจาก `availability()` (หลังบรรทัด 192).
**Algorithm = load once, fill matrix** (3 queries ตลอด ไม่ว่าจะกี่วัน — ไม่ใช่ N×M ในลูป):
1. validate `start_date`, `end_date` + ตรวจ cap 366 วัน
2. query room_types ทั้งหมดพร้อม `withCount rooms whereNotIn(status, [maintenance, reserved_closed])` (1 query)
3. query booking_rooms ที่ overlap `[start, end+1]` **ครั้งเดียว** (1 query)
4. PHP วนแต่ละ BR แล้ว fill occupied count ลง matrix `[room_type_id][date]` เฉพาะคืนใน [start, end]
5. compute `available = max(0, total − occupied)` แต่ละ cell

เพิ่ม use: `App\Models\BookingRoom`

### 2. `routes/api.php`
เพิ่มในกลุ่ม public `Route::prefix('v1')` ถัดจากบรรทัด 44:
```php
Route::get('/availability-per-day', [RoomController::class, 'availabilityPerDay']);
```

บันทึก endpoint ใหม่ + semantics (snapshot ณ today, ตรงกับ createBooking) + matrix approach + 366-day cap
