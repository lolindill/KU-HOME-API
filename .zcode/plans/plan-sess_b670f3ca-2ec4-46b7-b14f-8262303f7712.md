# Draft Booking Deletion + Draft BookingRoom Update/Delete

## สรุปงาน

เพิ่ม 3 endpoints (ทั้งหมด **เจ้าของ booking หรือ admin** เท่านั้น — ใช้ ownership pattern เดียวกับ `addRooms`):

| Method | Path | อนุญาตเมื่อ |
|---|---|---|
| `DELETE` | `/api/v1/bookings/{bookingId}` | booking status = `draft` |
| `PUT` | `/api/v1/bookings/{bookingId}/rooms/{bookingRoomId}` | booking = `draft` **และ** BR = `draft` |
| `DELETE` | `/api/v1/bookings/{bookingId}/rooms/{bookingRoomId}` | booking = `draft` **และ** BR = `draft` |

ตรงกับ "future work" ที่ลิสต์ไว้ใน `cline.md` (remove rooms + update individual room) พอดี — ไม่แตะ state machine classes (การลบ = hard delete ไม่ใช่ transition ใหม่)

## 1. `routes/api.php`

เพิ่มใน protected group (ใต้ `POST /bookings/{bookingId}/rooms` ~L86) ทั้ง 3 route + `where(uuid)` + `throttle:5,1`

## 2. `app/Http/Requests/UpdateBookingRoomRequest.php` (rewrite — ตอนนี้ไม่ถูกใช้ที่ไหนเลย)

Flat rules แบบ `sometimes` (ไม่มี `booking_id`/`room_id` — ห้าม user ตั้งเอง ตามกฎ RoomAllocator):
`room_type_id`, `check_in` (after_or_equal:today), `check_out` (after:check_in), `guests.*`, `has_children`, `bed_preference`, `billing_address/comment`, `extra_beds`, `addons.breakfast/early_checkin/late_checkout` + ข้อความไทยเหมือน `AddBookingRoomsRequest`

## 3. `app/Http/Controllers/Api/V1/BookingController.php` — 3 methods + helper

**`destroyBooking($bookingId)`**
- Guard: login 401 → `findOrFail` 404 → ownership 403 → status ต้องเป็น `draft` ไม่งั้น 422
- `DB::transaction`: โหลด booking ด้วย `lockForUpdate()` + re-check draft (กัน race กับ confirm/verify) → hard delete cascade แบบเดียวกับ `CleanupExpiredDrafts`: addon ของทุก BR → BR ทุกห้อง → payments (frozen table) → confirmations (defense-in-depth แม้ draft จะไม่ควรมี) → booking
- เขียน `StatusChangeLog` (`booking`, `draft → deleted`, note ระบุผู้ใช้ลบเอง) — เก็บ audit trail แบบ append-only ไว้แม้ row หาย
- Response 200 สำเร็จ

**`updateRoom(UpdateBookingRoomRequest, $bookingId, $bookingRoomId)`**
- Guard: login → booking 404 → ownership 403 → booking draft 422 → `$booking->bookingRooms()->where('id', $brId)->firstOrFail()` (BR ไม่อยู่ใน booking นี้ = 404) → BR draft 422
- `DB::transaction` + lock booking row + re-check:
  - Merge ฟิลด์ที่ส่งมาลง BR (ยกเว้น `room_id`, `status`, `booking_id` เสมอ)
  - ถ้าส่ง `room_type_id`/`check_in`/`check_out` มา → **availability re-check**: นับ BR overlap ของประเภทห้องเป้าหมาย `where('id', '!=', $br->id)` (ตัดตัวเองออก) เทียบจำนวนห้อง — pattern เดิมจาก `addRooms` L171-199
  - **Reprice server-side**: คิดราคาห้องใหม่จาก `GlobalRate` (room rate × nights + extra_bed × rate × nights + breakfast + early/late) แล้ว update/create แถว `Addon` ให้ตรง
  - คำนวณ `total_amount` ของ booking ใหม่ทั้งใบด้วย helper (idempotent)
- Response 200 พร้อม `booking_room` + `total_amount` ใหม่

**`destroyRoom($bookingId, $bookingRoomId)`**
- Guard เหมือน updateRoom + **ถ้าเป็นห้องสุดท้ายใน booking → 422** แจ้งให้ใช้ `DELETE /bookings/{id}` แทน
- ลบ addon → BR, เขียน `StatusChangeLog` (`booking_room`, `draft → deleted`), คำนวณ `total_amount` ใหม่
- Response 200

**Private helper `recalculateBookingTotal(Booking): int`** — รวมยอดทุก BR จาก current server rates (draft อายุ ≤24ชม. _rate drift_ ไม่มีนัยสำคัญ)

Error handling ใช้ pattern `addRooms`: business error 401/422 ส่ง message ได้, `ModelNotFoundException` → 404, ที่เหลือ log + 500 กลับ generic message

**คงเดิม**: `payment_deadline` ไม่รีเซ็ต (เหมือน addRooms), ไม่มีสถานะใหม่ใน state machine
