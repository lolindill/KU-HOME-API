## เพิ่ม API: `GET /api/v1/unavailable-dates`

คืน flat list วันที่จองไม่ได้เลย (ผลรวมห้องว่างทุก room type = 0) ในช่วง `[start_date, end_date]`

### Semantics (เทียบเท่ากับ availability-per-day/ranges ทุกอย่าง)
- `total_rooms` = ห้องที่ `status NOT IN (maintenance, reserved_closed)` (ตรง createBooking)
- `occupied` = booking_rooms status ∈ (draft, confirmed, checked_in) overlap คืนนั้น — half-open `check_in ≤ D < check_out`
- วัน "จองไม่ได้" = `sum over room_types of max(0, total − occupied) == 0`
- **Edge case (degenerate guard):** ถ้าไม่มี room type เลย หรือ **ทุก** room type total=0 → คืน `[]` (ไม่ใช่ทุกวัน) — ป้องกัน false-positive ใน dev/test

### การเปลี่ยนแปลง

**1. `app/Http/Controllers/Api/V1/RoomController.php`** — เพิ่มเมธอด `unavailableDates(Request $request)`:
- validate `start_date`/`end_date` (required, date, after_or_equal) — เหมือน `availabilityPerDay` เป๊ะ
- DoS guard: ช่วง > 365 คืน → `422`
- Query room types ด้วย `withCount(['rooms as total_rooms_count' => fn($q) => $q->whereNotIn('status', ['maintenance','reserved_closed'])])` — เหมือน `availabilityPerDay`
- Query booking_rooms overlap ครั้งเดียว + build occupied matrix `[room_type_id => [date => count]]` — reuse logic เดียวกับ `availabilityPerDay`
- คำนวณ per-day total availability = `sum(max(0, total − occupied))` ข้ามทุก room type
- **Degenerate guard:** ก่อนลูป — ถ้าไม่มี room type หรือ `sum(total_rooms_count) == 0` → คืน `unavailable_dates: []` เลย
- คืน `["date1","date2",...]` (ascending) ในฟิลด์ `unavailable_dates`

**Response 200:**
```json
{
  "status": "success",
  "message": "Unavailable dates fetched successfully",
  "start_date": "2026-08-10",
  "end_date": "2026-08-20",
  "unavailable_dates": ["2026-08-12", "2026-08-13"]
}
```

**2. `routes/api.php`** — เพิ่มใน public routes block (หลัง `/availability-ranges`):
```php
Route::get('/unavailable-dates', [RoomController::class, 'unavailableDates']);
```
