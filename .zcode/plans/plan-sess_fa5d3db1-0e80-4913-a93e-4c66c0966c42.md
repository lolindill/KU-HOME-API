# แผน: ระบบ images จริงจัง (private + signed URL) + ย้าย flow สลิปมาใช้ + cleanup

**การตัดสินใจที่ตกลงแล้วกับนายท่าน:** Disk + `images` table แบบ polymorphic (ไม่ใช่ BLOB) · สลิป private + ดูผ่าน **signed URL อายุ 15 นาที** · ขอบเขตแบบเต็ม (ถอด draft `/upload-image`) · cleanup ไฟล์สลิปเก่า

**ข้อค้นพบสำคัญจากการสำรวจ:**
- `config/filesystems.php:33-39` — `local` disk root = `storage/app/private` + `serve => true` อยู่แล้ว → ใช้ได้ทันที ไม่แต้ม config, ไม่ต้อง `storage:link` สำหรับสลิปอีกต่อไป
- ตอนนี้สลิปเก็บ public disk (`BookingConfirmationController.php:77`) + path string ใน column `booking_confirmations.slip_image`
- `images` table เป็น draft (`2026_04_27` migration) มีแค่ `url`, `imageable_id/type` หลวมๆ ไม่มี index
- จุดที่ confirmation ถูกลลบ: FK cascade จาก booking hard-delete (`destroyBooking` + `CleanupExpiredDrafts`) → image morph **ไม่** cascade เอง ต้องจัดการเอง
- `RequireJsonAccept` (prepend ทั้ง api group) จะตี `<img>` ที่ส่ง `Accept: image/*` เป็น 406 → ต้อง exempt เฉพาะ route ให้บริการรูป และ **document ใน cline.md ตามกติกา AGENTS.md**

## 4) Routes (`routes/api.php`)
- **ลบ** draft `POST /upload-image` + `use ImageController` import เดิมออกจากกลุ่ม public
- **เพิ่ม** `GET /api/v1/images/{image}/file` → `ImageController@show`, name `images.file`, middleware `signed` + `throttle:10,1` — วางนอกกลุ่ม `auth:sanctum` (signature คือตัวยืนยันตัวตน) และ `->withoutMiddleware(\App\Http\Middleware\RequireJsonAccept::class)` เพื่อให้ `<img Accept: image/*>` เข้าได้

## 5) `app/Http/Controllers/Api/V1/ImageController.php` — เขียนใหม่
- ลบ `upload()` ทิ้ง, ลบไฟล์ `app/Http/Requests/StoreImageRequest.php`
- `show(Image $image)` → `Storage::disk($image->disk)->response($image->path, null, ['Content-Type' => $image->mime_type])` (stream ไฟล์ inline)
- **สิทธิ์:** ไม่กังวลผู้ถือ URL — URL มีอายุ 15 นาที + ถูกออกให้เฉพาะใน response ที่คุมสิทธิ์อยู่แล้ว (เจ้าของ booking / admin)

## 6) `BookingConfirmationController` — ย้าย flow สลิป
- `confirm()`: store ไฟล์ → `$request->file('slip_image')->store('slips', 'local')` (ลง `storage/app/private/slips/`) → สร้าง confirmation → `$confirmation->slipImage()->create([...metadata, 'uploaded_by' => $user->id])` ทั้งหมดใน transaction เดิม · ใน catch เพิ่ม best-effort `Storage::disk('local')->delete($path)` กันไฟล์กำพร้าจาก rollback · response ใช้ `'slip_image_url' => $image->url` (signed URL)
- `verify()` / `reject()`: `$confirmation->fresh(['slipImage'])` เพื่อให้ response มี URL ไปด้วย
- `pending()`: eager load เพิ่ม `'slipImage'`

## 7) จุดลบ booking — เก็บกวาดรูป
- `BookingController::destroyBooking` (~line 363): ก่อน `$locked->confirmations()->delete()` → `$locked->confirmations->each(fn ($c) => $c->slipImage?->delete())` (hook deleting จะลบไฟล์ให้)
- `CleanupExpiredDrafts`: เพิ่มบรรทัดเดียวกันก่อนลบ confirmations

## 8) Cleanup command ใหม่ — `app/Console/Commands/CleanupImages.php`
`app:cleanup-images` สไตล์เดียวกับ `CleanupExpiredDrafts` (info/warn/Log summary):
1. **ไฟล์กำพร้า** — สแกน `Storage::disk('local')->files('slips')` ไฟล์ไหนไม่มี row ใน `images` → ลบ
2. **row กำพร้า** — image morph ไป confirmation ที่ถูกลบไปแล้ว (defense-in-depth นอกเหนือจาก step 7) + image ไม่มี imageable และแก่กว่า 24 ชม. → ลบ row (ไฟล์ถูกลบโดย hook)
3. **retention** — สลิปของ confirmation `rejected` ที่เก่ากว่า 30 วัน (env `SLIP_RETENTION_DAYS` ปรับได้) → ลบ image (คง confirmation row ไว้ตาม audit trail) · **สลิป `verified` เก็บไว้ทั้งหมด** (หลักฐานการเงิน)
- ลงทะเบียน `routes/console.php`: `Schedule::command('app:cleanup-images')->dailyAt('02:30')`
