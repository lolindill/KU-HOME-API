# Plan: Audit Log สำหรับ Booking & BookingRoom State Changes

## เป้าหมาย
เมื่อ status ของ Booking หรือ BookingRoom เปลี่ยน → บันทึก audit row ลง DB (ใคร/role/from/to/เมื่อไหร่) และเปิด endpoint ให้ admin อ่าน history ได้

## ขอบเขต (ตามคำตอบนายท่าน)
- ✅ Booking + BookingRoom เท่านั้น (Room/HousekeepingTask/BookingConfirmation ยังไม่ทำ)
- ✅ ตารางเดียว polymorphic (`status_change_logs`)
- ✅ มี endpoint อ่าน (admin only)

## 1) Migration ใหม่ — `database/migrations/2026_08_04_100000_create_status_change_logs_table.php`

```php
Schema::create('status_change_logs', function (Blueprint $table) {
    $table->uuid('id')->primary();
    $table->string('entity_type');          // 'booking' | 'booking_room'
    $table->uuid('entity_id');              // morph target (no FK constraint — polymorphic)
    $table->string('from_status');
    $table->string('to_status');
    $table->string('role');                 // role ที่ authorize transition ('admin'/'system'/...)
    $table->uuid('causer_id')->nullable();  // Auth::id() — nullable เพราะ system/queue ไม่มี user
    $table->text('note')->nullable();       // สำรองไว้ (เช่น 'auto via syncStatusFromRooms')
    $table->timestamps();

    $table->index(['entity_type', 'entity_id', 'created_at']); // query history ตาม entity + เวลา
});
```

**เหตุผล polymorphic:** นายท่านเลือกตารางเดียว polymorphic เพื่อขยาย entity ใหม่ง่ายในอนาคต (Room/HousekeepingTask). ไม่ใส่ FK constraint เพราะ morph target หลายตาราง — แลกกับความยืดหยุ่น (ความเสี่ยง orphan row ต่ำเพราะ row ถูกสร้างเฉพาะตอนที่ entity มีอยู่จริง)

## 3) แก้ `Booking::transitionStatus()` — `app/Models/Booking.php:114-145`

เพิ่มหลัง `$this->save();` (บรรทัด 144) ก่อนปิด method — ไม่แตะ signature (กัน breaking change กับ caller เดิมทั้งหมด):

```php
$this->status = $newStatus;
$this->save();

// 📝 Audit log: เก็บประวัติการเปลี่ยนสถานะ (ใคร/role/from/to/เมื่อไหร่)
StatusChangeLog::create([
    'entity_type' => 'booking',
    'entity_id'   => $this->id,
    'from_status' => $currentStatus,
    'to_status'   => $newStatus,
    'role'        => $userRole,
    'causer_id'   => Auth::id(),   // nullable — system/queue transition ไม่มี user
    'note'        => null,
]);
```

## 4) แก้ `BookingRoom::transitionStatus()` — `app/Models/BookingRoom.php:52-84`

เช่นเดียวกัน เพิ่มหลัง `$this->save();` (บรรทัด 83):

```php
$this->status = $newStatus;
$this->save();

// 📝 Audit log
StatusChangeLog::create([
    'entity_type' => 'booking_room',
    'entity_id'   => $this->id,
    'from_status' => $current,
    'to_status'   => $newStatus,
    'role'        => $userRole,
    'causer_id'   => Auth::id(),
    'note'        => null,
]);
```

**คำอธิบายการออกแบบสำคัญ:**
- **ทำไมไม่ใช้ event/listener/observer?** Project ตั้งใจหลีกเลี่ยง events (`cline.md:395` "No events/listeners … state changes are synchronous"). แถม observer ไม่เห็น `$userRole` (role guard อยู่ใน scope transitionStatus เท่านั้น) → ต้องเขียนใน transitionStatus โดยตรง
- **ทำไมไม่แตะ signature?** เพิ่ม causer_id เข้า signature = breaking change กระทบ caller ~12 แห่ง ใช้ `Auth::id()` ที่ resolve จาก request ณ runtime ดีกว่า (เทียบเคียงวิธีที่ Room::transitionStatusTo รับ userId เข้ามา แต่เราเลือกทาง non-breaking)
- **เกิด error ระหว่าง save log?** ไม่ใช้ try/catch ปกป้องเพราะทั้ง transitionStatus และ caller อยู่ใน DB transaction (เห็น `DB::beginTransaction()` ใน FrontDeskController) → log row จะ rollback ไปด้วยถ้า transition ที่ตามมา fail

## 5) Endpoint อ่าน log (admin) — เพิ่มใน `routes/api.php` ใต้ `role:admin` group

```php
// 📝 Status change logs (audit)
Route::get('/bookings/{id}/status-logs', [BookingController::class, 'statusLogs'])
    ->where('id', '[0-9a-f\-]{36}');
```

เพิ่ม method ใน `BookingController.php`:

```php
/**
 * 📝 Audit log: ประวัติการเปลี่ยนสถานะของ booking (container + ทุก booking_room ใน booking)
 */
public function statusLogs(string $id)
{
    $booking = Booking::with('bookingRooms')->findOrFail($id);

    // เก็บ log ของ booking container + ทุก booking_room ที่อยู่ใต้ booking นี้
    $brIds = $booking->bookingRooms->pluck('id');

    $logs = StatusChangeLog::where(function ($q) use ($id, $brIds) {
        $q->where(fn ($qq) => $qq->where('entity_type', 'booking')->where('entity_id', $id))
          ->orWhere(fn ($qq) => $qq->where('entity_type', 'booking_room')->whereIn('entity_id', $brIds));
    })
    ->orderBy('created_at', 'asc')
    ->get(['id', 'entity_type', 'entity_id', 'from_status', 'to_status', 'role', 'causer_id', 'created_at']);

    return response()->json([
        'status' => 'success',
        'message' => 'Status change logs retrieved',
        'logs' => $logs,
    ]);
}
```

Response shape ตามมาตรฐาน project: `{"status":"success","message":...,"logs":[...]}` — return model/collection ตรงๆ (ไม่มี Resource/wrapper — ตาม convention ใน AGENTS.md)

## 6) Tests — `tests/Feature/StatusChangeLogTest.php`

- สร้าง booking → transition draft→paid (role user) → ตรวจว่ามี row `entity_type=booking, from=draft, to=paid, role=user`
- ทำ booking_room confirmed→checked_in (role admin) → ตรวจ row `entity_type=booking_room`
- `syncStatusFromRooms()` → complete (role system) → ตรวจ row `role=system, causer_id=null`
- GET `/api/v1/bookings/{id}/status-logs` ด้วย admin → 200 + logs
- GET ด้วย non-admin → 403 (CheckRole บล็อก)
- ทดสอบ rollback: เกิด exception หลัง transition ใน transaction → log row ไม่ควรคงอยู่
